# V3.0-01 增量实现

## 仓库复用与边界

现有 Python 3.10+ CLI、Workspace 原子写入/运行目录/创作者锁、输入与 workspace 隔离规则、Source 引用/哈希以及 JSON Schema 合同继续使用。`VIDEO_EXTENSIONS` 从原媒体扩展集合提取，不改变 V1.0 扫描行为。视频分析单独扫描，只忽略音频/文本，不施加转写稿同名歧义规则。Meta/Evaluation/Optimizer Skill 和 Agent/ASR 接口无需变动；既有 V1/V2 运行目录和文案流程不被迁移或覆盖。

本阶段完全本地执行，不调用 Agent、ASR、网络服务或下载模型。没有 TTS、口型同步、视频合成或 Web 应用。

## 分层

- `video.py`：只读扫描、FFprobe 合同归一化、FFmpeg 全片解码/切镜/采样、Pillow 联系图和可选本地 Haar 人脸检测。`VideoAnalyzer` Protocol 隔离媒体提供方；实际输出不依赖 AI 解释。
- `video_assets.py`：素材候选索引、可核对证据、重复文件/相似画面候选、模板分组、Schema 和引用/时间边界检查、不可覆盖运行快照与中文报告。
- CLI：`analyze-video` 入口和依赖 doctor；原命令保留。
- `video-library.json`：独立可读 Schema。生成器 `scripts/build_video_schema.py` 单独维护，不改 V1/V2 Schema 生成器。

若后续加入视觉理解，必须采用单独 provider，将语义结论与确定性测量分开，保留输入帧/来源、证据、未知状态和实际可验证置信度；不应把人脸检测矩形或图像变化量当作人物身份、口部可见性或动作结论。

## 数据语义

`source_id` 沿用相对路径 SHA-256 前 16 位，`sha256` 为完整源内容哈希，既可关联原转写来源，也可识别原文件修改。文件路径为本机绝对引用；证据路径相对运行根目录。第一个非附加封面视频流为主分析流，全部音频流保留。时长优先视频流，缺失时取容器时长；无法取得可靠时长则该文件失败。

编码尺寸与显示尺寸分别保存。SAR 缺失按 1:1 计算且 `sample_aspect_ratio_assumed=true`。旋转取 Display Matrix 中旋转角优先于 rotate 标签；90/270 度交换显示宽高，并按 SAR 校正。关键帧明确关闭自动旋转，先归一化 SAR，再应用旋转；缩放采样为最多约 640 像素边长，适合筛查，不适合作为生产清晰度判断。任意角度为旋转后的外接矩形；镜像/复杂仿射变换未作为完整显示变换实现，应人工核查。

Display Matrix 返回角度按逆时针解释，参照 [FFmpeg 显示矩阵接口说明](https://www.ffmpeg.org/doxygen/trunk/group__lavu__video__display.html)。

切镜采用 FFmpeg `scene` 阈值；时间戳通过 `setpts=PTS-STARTPTS` 归零。候选镜头按完整时间轴连续覆盖，长镜头分段不跨切镜点。每个关键帧保存 FFmpeg showinfo 的实际 PTS，不把请求 seek 时间冒充实际帧时间。画面采样上限是每视频的；低帧率尾部 seek 会避开没有图像的帧间尾区，VFR/损坏流仍可能解码失败。

多个 seek 可能落在同一个实际帧，按解码时间戳去重后才生成联系图和相似画面组，避免把采样重复误当作原片重复使用。联系图标签对应真实关键帧编号，允许编号因去重产生空缺。

自动候选均保留 `category=null`、`confidence=null`、`status=pending_review`。`suggested_categories` 是启发式分类入口：采样有单张正面人脸建议 A/B；没有足够人脸证据建议 B/C/D/E；极端亮度或过短片段建议检查 E。采样人脸比例、面部框平均中心/面积、缩放脸部 Laplacian 方差只保留指标，不推断人物出镜总时长、表情、口部或身份。

相似画面组通过 16×16 灰度缩略图平均绝对差阈值建立，并明确标记待审核。这不是动作检测、场景识别或去重决定；内容相同的文件另用 SHA-256 识别。固定场景数目前为 `null`，切镜候选数不冒充场景数量。字幕流仅记录流索引，不推断烧录字幕、位置或遮挡。

模板按显示尺寸/比例和有理数帧率分组，使用正方形像素、零旋转、偶数尺寸，按组总时长标记首选。该模板不是平台兼容性或后续生成模型输出参数的验收结果；VFR/奇数尺寸/任意角度仍需下一阶段实际编码验证。

## 持久化与审核

每次运行 UUID 独立，成功/部分成功资产库通过 Schema 和时间/引用核查后写入 `library.json`；每处理一个来源写入未完成的检查点。错误、日志和已完成关键帧留在 workspace。单文件异常不阻止其余文件；全失败有报告，退出码 1，不替换最新可用资产库。人工中断保留检查点并释放锁。`video-assets/latest.json` 只是可用运行引用，不是生产可用审核。

`review-template.json` 将全部视觉检查项置为待审核，供人工记录分类、场景 ID、署名与证据；此阶段不实现审核合并或发布，因此不能靠修改工作表假装自动检测结果已确认。下游须同时检查源文件哈希、真实原片、人工证据和适用性。大视频不复制、不裁剪、不生成新成片；人物/声音第三方服务需要新授权。

## 工程验证

`tests/test_video_assets.py` 包含真实 FFmpeg 执行的合成横屏、竖屏、已知 1 秒切镜、AAC 48kHz、无音频、旋转+SAR、异常文件、原文件哈希/mtime 不变、分页联系图文件、Schema/证据边界、采样上限、CLI 返回码、源文件变更、全失败 latest 不变和中断保留测试。纯合同样本验证可选人脸候选状态，明确不代表实际模型质量。

`scripts/validate_v3_video.py` 在新建的合成素材文件夹运行完整分析并保留可人工打开的 `validation.json`、报告和资产库。视频全部由 FFmpeg 合成，无真实创作者人像；验证实际本地工具和流程，不能证明真实场景理解、风格质量或口型同步质量。
